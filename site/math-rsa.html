Math Behind Tech · Chapter 01

RSA and public-key cryptography

Two small primes, one multiplication, and the padlock the whole internet uses. Every number on this page is small enough to check with a pencil, and every one of them has been.

Plain text is theory. Cream sheets are worked examples: problem, working, answer.

Where you meet it

RSA is named after Rivest, Shamir and Adleman, who published it in 1978. You touch it several times a day without noticing.

HTTPS

The padlock in your browser. The site's certificate carries an RSA signature, and your browser checks it with the operation in Example 4 before trusting the site.

SSH keys

ssh-keygen -t rsa writes two files into your home directory. They hold exactly the numbers in Example 1, just 2048 bits long instead of 6.

JWT · RS256

An auth server signs a token with its private key. Every service verifies it with the public key and never has to call the auth server back.

Signed commits and packages

The "Verified" badge on a git commit, and the signature your package manager checks before installing anything, are RSA signatures most of the time.

The idea in one breath

A normal lock has one key: whoever can lock can unlock. That is symmetric encryption, such as AES, and its weak point is obvious. Two computers that have never met must agree on a key over a wire anyone can listen to. Send the key, and the listener has it too.

RSA is a lock with two keys. The public key only locks, so you hand it to everyone. The private key only unlocks, so you keep it. Anyone can lock a message for you. Only you can open it.

In numbers: pick two primes p and q and multiply them to get n. Publish n with a second number e. Keep a third number d secret. Encrypt with c = me mod n, decrypt with m = cd mod n. It holds because multiplying p × q is instant, while recovering p and q from n is, at real sizes, beyond every computer on Earth.

The four tools you need

Nothing below needs more than these four ideas.

1. Prime numbers

A prime is a whole number above 1 that only 1 and itself divide evenly: 2, 3, 5, 7, 11, 13, and so on.

3. Coprime numbers

The greatest common divisor, gcd, is the largest number dividing both. Two numbers are coprime when it is 1.

4. The modular inverse

In ordinary arithmetic the inverse of 3 is ⅓, because 3 × ⅓ = 1. In clock maths with n = 20, the inverse of 3 is the whole number d with 3 × d mod 20 = 1. It exists only when the two numbers are coprime. Python has it built in as pow(3, -1, 20).

3 × 7 = 21 = 1 × 20 + 1

Build the keys

Five steps. Real RSA runs the same five with primes about 300 digits long.

  1. Pick two primes, p and q

    In production they come from a random number generator and a primality test, and are never reused.

  2. Multiply them: n = p × q

    n is public, and from now on every message and ciphertext is a number between 0 and n − 1.

  3. Compute the totient: φ(n) = (p − 1)(q − 1)

    Euler's totient counts the numbers from 1 to n that are coprime with n. This is the secret ingredient: the formula needs p and q, so anyone who has only n must factor it first.

  4. Choose the public exponent e

    Any number above 1, below φ(n), and coprime with it (tool 3). Production almost always uses 65537.

  5. Find the private exponent d

    The modular inverse of e (tool 4): the number with e × d mod φ(n) = 1.

Encrypt a message

RSA works on numbers, so letters become their alphabet position: A = 1, B = 2, up to Z = 26. Every letter is below 33, which matters. A message must be smaller than n, or mod n throws part of it away for good. Encryption is c = me mod n, and it needs only the public key.

The ciphertext is 17, 3. Send it over any wire. Anyone can read those two numbers, and anyone could have produced them, because this step uses only the public key.

Decrypt it

Decryption is m = cd mod n, so we need 177 mod 33. Raw, 177 is 410,338,673. Nobody divides that by hand. Tool 2 lets us square, reduce, and repeat, so the numbers stay small. This square-and-reduce loop is exactly what Python's pow(c, d, n) does.

Turn it around: signatures

Encryption used the public key first and the private key second. Do the same two operations in the opposite order and you get a digital signature: only the holder of d can produce it, and anyone with (n, e) can check it. This is what JWTs, SSH logins and TLS certificates actually use RSA for. In practice you sign a fixed-size hash of the document, so the thing signed is always smaller than n.

Why it works

Euler proved in 1763 that if m and n are coprime, then mφ(n) mod n = 1: raising anything to the totient brings you back to 1. We chose d so that e × d is 1 more than a multiple of φ(n). Put the two together and the exponents cancel.

20 is exactly the exponent that Euler says turns any coprime m into 1, so m²¹ is m again. That is the entire reason d undoes e, and why φ(n) rather than n is what you need to build the private key.

One honest footnote

Euler's theorem needs m coprime with n. The letter I is 9, which shares the factor 3 with 33, and it still decrypted correctly in Example 3. RSA works for those values too, by a separate argument through the Chinese remainder theorem. With real primes the chance of a message sharing a factor with n is negligible.

Why it is secure, and why 33 is not

Breaking RSA is the key generation steps run backwards, starting from a factorisation of n. Sit in the attacker's chair.

Example 6

Break the key (33, 3)

You know only the public key (33, 3) and have intercepted c = 17. Recover the letter.

Factor the modulus
33 = 3 × 11
p = 3, q = 11
Recompute the totient
(3 − 1) × (11 − 1) = 2 × 10
φ = 20
Recompute the private exponent
3 × 7 = 21 = 1 × 20 + 1
d = 7
Decrypt, as in Example 3
17⁷ mod 33
8 = H

Broken in four lines. Every line was easy except the first, and the first was easy only because 33 is small.

A real modulus has 2048 bits, which is 617 decimal digits, with two 309-digit primes hidden inside. The largest RSA modulus factored publicly so far is 829 bits, RSA-250, and that took a research team thousands of core-years in 2020. With the best known algorithms each added bit multiplies the work, so 2048 bits is not "a bit more than twice as hard" as 829. It is beyond every computer on Earth for longer than anyone plans to keep a key.

Two caveats. The difficulty is an observation, not a proof: nobody has shown factoring must be slow, only that decades of trying have not made it fast. And Shor's algorithm from 1994 would factor n quickly on a large enough quantum computer, which is why NIST standardised post-quantum replacements in 2024 and long-lived systems are already migrating.

Run it

Build it: the same numbers in twenty lines

Standard library only, Python 3.8 or newer. Every printed value matches Examples 1 to 4.

# RSA with numbers small enough to check on paper.
# Companion to math-rsa.html. Spec: RFC 8017 (PKCS #1 v2.2).
from math import gcd

p, q = 3, 11
n = p * q                    # 33 -> the public modulus
phi = (p - 1) * (q - 1)      # 20 -> Euler's totient, keep secret
e = 3                        # public exponent, must be coprime with phi
assert gcd(e, phi) == 1
d = pow(e, -1, phi)          # 7  -> private exponent: (e * d) % phi == 1

print(f"public key  (n, e) = ({n}, {e})")
print(f"private key (n, d) = ({n}, {d})")

msg = "HI"
m = [ord(ch) - 64 for ch in msg]          # A=1 ... Z=26, every letter below n
c = [pow(x, e, n) for x in m]             # encrypt: m^e mod n
back = [pow(y, d, n) for y in c]          # decrypt: c^d mod n
print("plaintext ", m)
print("ciphertext", c)
print("decrypted ", "".join(chr(x + 64) for x in back))

s = pow(8, d, n)                          # sign 8 with the private key
print("signature ", s, "-> verifies:", pow(s, e, n) == 8)
$ python3 rsa_by_hand.py

Toy vs production

Every operation on this page is the real one. What changes at scale is the size of the numbers, plus a layer of rules that stop clever attacks.

This pageReal RSA
p, q3 and 11Two random primes of about 1024 bits each, tested with Miller–Rabin, never reused.
n332048 bits at minimum; 3072 or 4096 for keys that must last years.
e365537. A small e with unpadded messages is a known weakness.
messageOne letter, rawNever raw. Padded with OAEP for encryption or PSS for signatures (RFC 8017), which adds random bytes so the same input encrypts differently every time.
repeatsH is always 17An eavesdropper could count how often 17 appears and guess the letter. Padding removes the pattern.
what is encryptedThe message itselfA random AES key. The data is encrypted with AES, which is thousands of times faster; RSA only protects the key.
in TLS 1.3EverythingSignatures only. The session key comes from Diffie–Hellman (RFC 8446), so a stolen RSA key cannot decrypt recorded traffic.
timingIrrelevantThe private-key step must take the same time regardless of the bits in d, or an attacker measuring response times can recover it.

The private exponent equals the public one, so anyone holding the public key can decrypt. This only happens with toy-sized numbers; with real primes the odds are negligible and key generators check anyway. A good reminder that "the maths works" and "the key is safe" are different questions.

Why is e = 2 not allowed with φ(n) = 20?

gcd(2, 20) = 2, so no inverse exists. Concretely, 2 × d is even for every d, and an even number mod 20 stays even, so it can never equal 1. The search for d would run forever.
